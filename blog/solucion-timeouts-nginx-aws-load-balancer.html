Solución a Timeouts en Nginx con AWS Load Balancer

nginx aws load-balancer proxy_pass timeouts dns alb

Si usas Nginx para enrutar tráfico hacia un AWS Load Balancer, es posible que te hayas encontrado con timeouts intermitentes (upstream timed out). Esto sucede porque los IP del load balancer cambian dinámicamente, pero Nginx solo resuelve el DNS una vez al iniciar.

El Problema

Cuando configuras proxy_pass en Nginx con la URL de un Application Load Balancer (ALB) o Network Load Balancer (NLB), Nginx resuelve la dirección IP en el arranque y no actualiza los cambios de IP.

Esto funciona inicialmente, pero falla cuando el ALB cambia sus IPs.

Solución: Resolver el DNS en cada solicitud

Para evitar este problema, debes hacer que Nginx resuelva el DNS dinámicamente en cada request.

1 Agregar un resolver

Configura un servidor DNS para que Nginx siempre obtenga la IP actualizada del Load Balancer. En AWS, el servidor DNS es la IP base de tu VPC + 2 (por lo general, 10.0.0.2).

Esto hace que Nginx respete el TTL del DNS y actualice la IP automáticamente.
